When dealing with a parameter that might be injectable, you want to make sure that the sqlmap command is formatted correctly, you can do this using the Copy as cURL from the network tab in devtools. to check a GET parameter use this command
```
sqlmap "example.com/index.php?vuln=x" -p vuln
```
for a POST request try this:
```
sqlmap "example.com/index.php" --data "vuln=x&id=3" -p vuln
```
you can also use the \* operator to specify the parameter
```
slqmap "example.com/index.php" --data "vuln=x*&id=3"
```
##### requests from a file

sqlmap -r req.txt

### Custom SQLMap Requests
Some times you want to customize the request, you can do this using some options.
- **--cookie** : used to specify a cookie with a request
- **--host** : used to specify the host header
- **--referer** : used to specify the referer header
- **-H**/**--host** : used to specify a header
- **--random-agent** : used to randomize the user-agent of the request
- **--mobile** : used to send mobile user-agent headers with the requests
- **--method** : used to specify the method of the request (e.g. PUT,POST,PATCH...)
If you want to test the headers like `cookie` and `referer` you do this by specifying the headers switch with the custom injection mark `*` like the following:
```
slqmap -u "example.com/index.php" --cookie="uid=*"
```
### Handling Errors
If you encounter errors when using sqlmap there are some switches that help you to resolve such errors.
- **--parse-errors** : displays the errors given by the DBMS (if any)
- **-t** : stores the traffic generated by sqlmap into a file for inspection
- **-v n** : the verbosity level (n=int), the tool is verbose
- **--proxy** : with this syntax `"http://127.0.0.1:8080"`, routes all traffic thru proxy
### Attack Tuning
Some times you want to tune the attack for a specific target. SQLMap has alot of tuning capabilities, let's go over some of them.
#### Prefix/Suffix
There are two parts of sqlmap payloads:
- **vector**: central part of the payload, has the useful SQL query 
- **boundaries**: **prefix**(before) and **suffix**(after) used for proper injection 
If you know the SQL query the server issues, you can add a prefix and a suffix to every payload sent by sqlmap, let's take the following query as an example:
```
SELECT * FROM users WHERE username = (('userinput'))
```
In this case, simply using the `'` is not sufficient to close the statement correctly. To close it correctly you need to start with `'))` and that is called a **prefix**. SQLMap lets you define a custom prefix using `--prefix` and the same goes to suffix using `--suffix`
#### level/risk
- the option `--level=(1-5)` extends the number of vectors and boundaries, the higher the number, the less likely the payload will succeed (because the payload is uncommon)
- the option `--risk=(1-3)` extends the used vector set based on their risk of causing problems to the server (try to avoid using risk=3 in production servers)

There are other tuning options to further adapt to the target behavior, these are some of them:
#### Status Codes
If the server gives you different status codes based on your input, example like a server that gives you 500 when you provide an invalid (false) sqli payload and a 200 when providing a valid (true) one. You can use the `--code=200` switch and provide the true statement code, this way sqlmap will differentiate between good and bad payloads.
#### Titles
The server might change the title of the page given multiple payloads. Use the `--titles` switch to make sqlmap check the \<title\> tag for changes.
#### Strings
In case a string appears in True responses and disappears in False ones like the `success` string. You can specify the string using the `--string=str`  switch.
#### text-only
If the page has a lot of hidden content like script, style, meta tags we can use the `--text-only` switch to remove all HTML tags and bases the comparison on text only 
#### Techniques
If the server is vulnerable to some types of SQLi you can choose them to shorten the time or you can choose what you prefer. For example, a server has a blind boolean-based sqli and a union sqli, it's better to choose the union injection technique using `--technique=U`
### UNION SQLi Tuning
In some cases, SQLMap's UNION payloads require user intervention.
#### number of columns
If you know the number of columns the table has you can provide using the `--union-cols=int` switch. 
#### data type
Another thing is the data type for the column, sqlmap by default uses integers and NULL for the filling, you can tell it to use a string -char- using the `--union-char='char'` switch. 
#### select from
Oracle requires you to select from a table when using union, if sqlmap didn't recognize the DBMS, it won't select from a table when interacting with oracle which results in an error thus a failed exploitation, you can force sqlmap to select from a table using the `--union-from=table_name`
### Database Enumeration
After a successful exploitation, the first step is enumeration which basically means gathering information. These are some of the switches to use in this phase:
- **--banner** : grabs the banner of the data base containing the version and name
- **--current-user** : grabs the current username
- **--hostname** : grabs the hostname of the DBMS server
- **--current-db** : grabs the current database
- **--tables** : grabs all the names of the tables in the current-db
- **-D,-T** : choose a database and a table respectively
- **--dump** : dump the contents of the chose table/database
- **-C** : specify the columns by name (separated by a comma)
- **--start,--stop** : start at \<int\> number and stop at \<int\> number respectively
- **--where** : to narrow down the search by matching
- **--dump-all** : dump all the contents in the DBMS
- **--exclude-sysdbs** : to exclude system databases (preferable with --dump-all)
#### Advanced Enumeration
- **--schema** : get the architecture of the database (table/column names, datatypes)
- **--search** : search for a table/column like `--search -T/C table/column name`
- **--passwords** : grabs the passwords of the DBMS users and cracks them
- **--all** : does all of the above and stores it for manual inspection
### Web App Protections Bypass
#### CSRF Token
alot of websites require a valid csrf token to be sent with a request - namely a POST request-, the server randomly generates the token and it can be found the source code of the page with the hidden attribute, you can tell sqlmap to check the GET response for CSRF token and send them in the POST request using the `--csrf-token` switch with the parameter name 'csrf-token'.
#### Randomized parameter
You might encounter an application that has a parameter with a random value that changes with each request, if two requests sent with the same value the second request will be dropped. you can tell sqlmap to randomize the value of a parameter using the `--randomize=param` switch.
#### Calculated parameter
If the server expects a calculated parameter that is based on another one like:
`http://example.com/index.php?id=1&h=c4ca4238a0b923820dcc509a6f75849b`
the `h` parameter is the MD5 hash equivalent to the `id` parameter value, you can tell sqlmap to calculate this using the `--eval=python_code` switch providing a python code:
`--eval="import hashlib;h=hashlib.md5(id).hexdigest()"`
#### IP Address Concealing
If the server is blocking your IP there are several ways to bypass the blockage:
- **--proxy** : requests from sqlmap go thru a proxy
- **--proxy-file** : like `--proxy` but with multiple proxies
- **--tor** : if tor is installed successfully sqlmap will use it as a proxy
- **--check-tor** : use it if you want to check if tor is working properly
#### User-Agent Black-listing
If you encounter a 5xx error code from the start, the server might drop all the requests with the sqlmap default user-agent. simply use the `--random-agent` to bypass this protection
